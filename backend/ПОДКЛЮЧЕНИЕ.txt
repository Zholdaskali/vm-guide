СЕРВЕР ЖИВОГО ПРОГРЕССА — SUPABASE

Статический конструктор работает без сервера. Живой режим не включается, пока не развёрнут backend и не заполнен online/config.js.

Развёртывание:
1. Применить SQL backend/supabase/migrations/202610160001_vm_classroom.sql в выделенном Supabase-проекте.
2. Развернуть функцию vm-classroom из backend/supabase/functions/vm-classroom с verify_jwt=false. Она сама проверяет непрозрачные токены студентов и секрет преподавателя.
3. Создать случайный секрет преподавателя (минимум 32 случайных байта), сохранить его только у преподавателя. Записать только SHA256 секрета в vm_settings.teacher_hash, singleton=true. Оригинал секрета в репозиторий не добавлять.
4. В online/config.js указать публичный HTTPS endpoint функции и при необходимости публичный publishable key проекта. Service role, secret key и пароль БД здесь запрещены.
5. Открыть online/teacher.html, ввести секрет преподавателя, создать группу и отправить студентам ссылку с восьмизначным кодом.

Обновление пульта — каждые 3 секунды через API. Это не WebSocket-подписка. Баллы и состояния вычисляет функция по действиям студента; готовые баллы с клиента не принимаются. Изменения имеют номер revision для защиты от потерянных обновлений при двух вкладках.

У таблиц включён RLS; anon/authenticated не могут напрямую читать или менять строки. Доступ только через функцию с серверным service role. У пульта отдельный секрет, клиентские отчёты его не содержат. Токены студентов хранятся на сервере как SHA256.

В публичный GitHub отправляются лишь код и общедоступные настройки. Фактические секреты не публикуются. Наличие кода backend в репозитории не означает, что он развёрнут.
